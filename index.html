CPU Scheduling

CPU Scheduling is the process by which the operating system decides which ready process is allocated the CPU for execution. Its primary goal is to ensure fairness, maximize CPU utilization and throughput, while minimizing turnaround time, waiting time, and response time.

1. Essential Formulas

Metric Formula Description
Turnaround Time (TAT) CT − AT Total elapsed time from arrival to completion
Waiting Time (WT) TAT − BT Total duration spent waiting in the ready queue
Response Time (RT) First Start − AT Time from arrival until first CPU execution
CPU Utilization (%) (ΣBT / Total Time) × 100 Percentage of time CPU was actively running processes
Average TAT / WT ΣValues / N Arithmetic mean across all N processes

2. Terms & Definitions

Term Full Name Meaning / Usage
PID Process ID Unique identifier for each process (P1, P2, P3...)
AT Arrival Time Clock time when the process enters the ready queue
BT Burst Time Total CPU execution time required by the process
CT Completion Time Clock time when the process completely finishes
QT Time Quantum Fixed time slice given per turn in Round Robin
IDLE CPU Idle Intervals where no arrived process is ready to execute

3. Scheduling Algorithms

Algorithm Type Scheduling Rule & Behavior
FCFS Non-Preemptive Dispatches in order of arrival (FIFO). Simple, but vulnerable to Convoy Effect.
SJF (NP) Non-Preemptive Selects ready job with shortest burst time. Runs until complete without interruption.
SJF (Preemptive) Preemptive (SRTF) Shortest Remaining Time First. Preempts current job if newly arrived job is shorter.
Priority P or NP Runs highest priority job. Supports higher/lower number rule. Preempts in P mode.
Round Robin Preemptive Time-sharing cycle. Each job gets Time Quantum (QT); if unfinished, goes to back of queue.

4. Tie-Breaking Rules

When multiple processes have equal priority or remaining burst time:

  1. Earlier Arrival Time (AT)
  2. Lower Process ID (PID, e.g. P1 before P2)
